# 创业板 × 中证红利｜市场风格观察仪表盘

基于**创业板指数（399006.SZ）**与**中证红利指数（000922.SH）**的历史走势与相对比值，辅助观察成长与红利风格变化的轻量级金融数据仪表盘。

> **定位声明：个人使用的市场风格研究工具，不提供买卖或仓位调整建议，不构成任何投资建议。**

- 纯静态部署：React + Vite 构建，GitHub Pages 托管，无后端、无数据库、无须登录
- 真实历史数据：项目内 JSON 随仓库保存，浏览器一次加载后全部交互在本地内存完成
- 自动更新：GitHub Actions 每个交易日收盘后增量更新，数据变化自动提交并触发重新部署
- 全端适配：PC / 平板 / 手机 / 微信内置浏览器共用同一网址与代码

## 功能一览

- **四张核心指标卡**：当前相对比值（含参考状态与距 0.300/0.700 参考线差值）、创业板指数、中证红利指数（最新收盘 + 当日涨跌幅 + 数据日期）、历史参考区间位置条（越界时提示「低于/高于参考区间」）
- **核心走势图**（Apache ECharts 双纵轴）：
  - 左轴 = 创业板指数点位，右轴 = 创业板 ÷ 中证红利相对比值，严格分轴
  - 0.300（绿色虚线）/ 0.700（红色虚线）固定参考线，缩放、切换时间范围、隐藏曲线时持续显示
  - 全历史最低/最高比值圆点标记，点击查看当日两个指数点位与比值
  - 十字准星、滚轮缩放、拖动、底部 DataZoom 滑块、双击/按钮重置；支持一键全屏查看（PC 铺满浏览器窗口；移动端模拟横屏显示，ESC 或按钮退出）
  - 数据指针浮层始终展示当日**真实行情记录**，缺失日期不编造
- **两组独立的时间控制**：坐标刻度（年/月/日，仅改横轴粒度与日期格式）与快捷范围（近1年/3年/5年/全部，切换可见窗口）；绘图始终使用原始有效交易日数据
- **手机专项**：与 PC 相同的单图双轴布局（同一张图对比双曲线与参考线）；一键全屏后横屏显示（Android 原生锁定横屏，iPhone/iOS 覆盖层 + CSS 旋转兑底，物理旋转设备时自适应）；触控区域 ≥44px；单指走滑块平移、双指缩放；浮层自动避让边缘；支持刘海屏安全区
- **说明弹窗与风险提示**：底部固定入口 + 悬浮按钮；PC 居中弹窗、手机底部抽屉；支持 X / ESC / 遮罩点击关闭
- **克制动效**：卡片顺序淡入、数字滚动、曲线首次绘制动画；全部动效遵循系统「减少动态效果」偏好

## 快速开始

环境要求：Node.js ≥ 20。

```bash
npm install        # 安装依赖
npm run dev        # 本地开发（http://localhost:5173）
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm run preview    # 本地预览生产构建（http://localhost:4173）
```

仓库已附带初始化完成的真实历史数据（`public/data/`），克隆后 `npm run dev` 即可直接使用，**无需**先跑数据脚本。

## 数据脚本

```bash
npm run data:init        # 首次初始化：拉取全历史并生成 historical.json / metadata.json（幂等）
npm run data:update      # 增量更新：只拉取缺失区间 + 最近约 5 个交易日的修正窗口（幂等）
npm run data:validate    # 数据校验：schema / 排序唯一 / 比值一致性 / metadata 一致性
npm run data:integrity   # 全量完整性检查：重新下载全历史比对，自动修复小规模差异
```

### 数据存储结构

```text
public/data/
  historical.json   # [{ date, chinextClose, dividendClose, ratio }, ...] 按日期升序
  metadata.json     # 数据来源 / 口径 / 指数代码 / 起止日期 / 版本 / 条数等
```

- `ratio` 存储保留 **6 位小数**，界面展示 3 位；前端所有计算直接使用存储精度值
- `metadata.version` 每次数据变化 +1；前端通过它做浏览器缓存失效（详见下文「缓存机制」）

### 更新脚本的可靠性设计

- **幂等**：同一天多次运行不会产生重复记录；无新交易日时不写文件、不触发部署
- **增量**：每次只请求「本地最新日期前 10 个日历日 ~ 最大可接受交易日」的区间，覆盖新增与近期修正
- **业务日基准 = 北京时间（Asia/Shanghai）**：工作日 15:05 后才接受当日数据；周末/节假日/盘中运行自动落到上一有效交易日
- **异常保护**：新数据收盘价无效或相对上一交易日波动 > 15% 时中止并保留旧版本；网络失败不清空历史；缺失日期不填 0、不伪造
- **原子写入**：先写临时文件并校验可解析，再替换正式文件，避免更新中断损坏数据
- **全量完整性检查**：每周独立运行（见 CI），重新拉取全历史与本地逐日比对；差异 ≤10% 自动修复并留痕，>10% 视为数据源口径变化而中止

## 数据来源与口径

| 项目 | 说明 |
|---|---|
| 主数据源 | 东方财富 push2his 行情接口（公开、无需密钥） |
| 备用数据源 | 腾讯财经日K接口（主源失败自动降级） |
| 指数代码 | 创业板指 `399006.SZ`（东财 secid `0.399006`）；中证红利 `000922.SH`（东财 secid `1.000922`） |
| 行情口径 | 日K线收盘点位（不复权），仅保留两个指数同日均有收盘数据的交易日 |
| 当前覆盖 | **2010-06-01 ~ 2026-10-16，共 3975 条**（中证红利自 2009-10-30 起有数据，创业板指 2010-06-01 起） |
| 时间轴起点 | 2009-10-30（创业板市场开市日）。创业板指数基日为 2010-05-31、发布更晚，**指数发布前的时间轴保留空白，不编造数据** |

**防错标的机制**：深市个股「佳电股份」代码同样是 000922（secid 应为 `0.000922`）。数据脚本对接口返回的 `code` 与 `name` 做双重断言（必须为 `399006`/`创业板指`、`000922`/`中证红利`），任何不符立即终止，确保不会取错标的。

**数据真实性验证**：最近 5 个交易日的两个指数收盘价已与腾讯财经源逐日交叉核对，10/10 完全一致；2024-09-30 / 2024-10-08 创业板指单日波动超过 15% 为真实行情（924 行情），校验脚本会以提示（而非错误）方式列出供人工复核。

### 缓存机制（网页访问流程）

1. 浏览器以 `no-store` 请求 `metadata.json`，判断数据版本
2. 以 `historical.json?v=<版本>` 加载历史数据（可长期缓存；部署新数据后版本号变化 → URL 变化 → 缓存自动失效）
3. 校验 metadata 与 historical 一致（条数 + 最新日期），不一致时明确报错并提示刷新，**绝不静默展示过期数据并标注为最新**
4. 数据保存在页面内存中，图表切换 / 缩放 / 拖动 / 刷新时间范围均不再发起行情请求

顶部的「刷新数据」按钮仅重新检查**已部署的数据版本**并读取最新文件；它不直接请求交易所行情，也没有服务端更新权限。

## 自动更新（GitHub Actions）

`.github/workflows/update-data.yml`：

- 定时触发：UTC `0 8 / 30 9 / 30 10` 的周一至周五，即**北京时间 16:00 / 17:30 / 18:30**（A 股 15:00 收盘，覆盖数据商日K更新完成的时间窗）
- 幂等执行 `data:update` + `data:validate`；数据有变化时自动提交 JSON 并 push → 触发 Pages 重新部署；无变化则跳过提交
- 支持手动运行（workflow_dispatch）
- ⚠️ GitHub Actions 定时任务可能延迟数分钟甚至更久，不能保证精确分钟执行；多时段触发 + 脚本幂等保证最终一致

`.github/workflows/check-integrity.yml`：北京时间每周六 10:00 运行全量完整性检查（周六休市），发现早期缺口与数据源修订并自动修复。

`.github/workflows/deploy.yml`：push 到 `main` 自动构建并部署 GitHub Pages。

## GitHub Pages 部署步骤

1. 在 GitHub 创建仓库，将本项目推送到 `main` 分支：

   ```bash
   cd chinext-dividend-dashboard
   git init && git add -A && git commit -m "init: 创业板×中证红利风格观察仪表盘"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```

2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**
3. 等待 `构建并部署到 GitHub Pages` 工作流完成，即可通过 `https://<用户名>.github.io/<仓库名>/` 访问
4. 之后每个交易日 16:00 后数据自动更新并自动重新部署（也可在 Actions 页手动运行更新）

> Vite `base` 已配置为相对路径 `./`，无论部署在用户页根路径还是项目子路径均无需修改。

## 环境变量

当前两个数据源均为公开接口，**无需任何密钥**。若未来接入需要授权的供应商：

1. 在 `scripts/lib/providers/` 实现新的 `IndexProvider`（参考 `eastmoney.ts`），加入 `providers/index.ts` 的数组
2. 密钥统一走环境变量（本地 `.env`、CI 用仓库 Secrets，如 `DATA_PROVIDER_API_KEY`），代码中通过 `process.env` 读取，不落库
3. `metadata.source / sourceName` 会记录实际使用的数据源，前端自动展示

## 常见数据异常处理

| 现象 | 处理方式 |
|---|---|
| 接口无法访问 / 返回空数据 | 自动降级备用数据源；全部失败则本轮更新中止，线上保持上一有效版本 |
| 数据源修改了历史值 | 更新窗口内自动吸收修正；早期差异由每周全量完整性检查发现并修复 |
| 新数据收盘价异常 / 波动 >15% | 更新中止并保留旧版本，日志中给出具体日期与数值 |
| 两指数日期不一致 | 仅保留同日均有收盘的交易日；单边缺失日不生成比值 |
| metadata 与 historical 不一致 | 前端明确报错提示刷新，不静默展示 |
| 节假日 / 当日未收盘 | 不生成新记录，页面继续展示上一有效交易日，顶部「数据截至」如实反映 |
| 早期历史缺口 | 每周全量完整性检查自动补齐（差异超阈值时中止并告警） |

## 已知限制

- 公开行情接口无 SLA，供应商可能调整结构（已做双源兜底 + code/name 断言，极端情况需更新适配层）

- 0.3 / 0.7 为用户指定的研究参考阈值，非统计检验结论；历史极值不代表买卖点
- 需要浏览器支持 ES2019+（主流现代浏览器与微信内置浏览器均满足）
